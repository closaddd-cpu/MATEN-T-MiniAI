FULL PRETRAINING, LORA AND SAFETENSORS GUIDE

REQUIREMENTS
------------
Architecture: 100,062,768 parameters, 6,144-token context, 16,384-token
SentencePiece BPE tokenizer. The base starts from random initialization.
Source checkout does not include trained model weights.

For pipeline tests, use a recent CPU, 16 GB system RAM and SSD.
For practical GPU training, a supported NVIDIA CUDA GPU with at least
approximately 12-24 GB VRAM is worth considering for shorter sequences;
more GPU VRAM can be required by large batch sizes or a full 6K context.
These are estimates, not guarantees. CPU-only is possible but very slow.
An AMD GPU requires a compatible PyTorch/ROCm stack. Check exact support.
Plan for dataset storage and potentially multi-gigabyte optimizer checkpoints.

INSTALL
-------
Install Python 3.10+, an appropriate PyTorch build and dependencies:
https://pytorch.org/get-started/locally/

  python -m pip install -r requirements.txt
  python brand_guard.py
  python -m unittest discover -s tests -v

FULL PRETRAINING FROM SCRATCH (NO 100-STEP CAP)
---------------------------------------------
  python train_full.py

This command builds/validates 94 generated JSONL shards if needed, trains a
SentencePiece tokenizer on train-only samples, trains the entire pretraining
split for one epoch and exports SafeTensors at completion. The generated data
contains up to 9.4M largely synthetic examples, including 8.46M training
rows; the number of processed tokens depends on actual tokenization.

CUDA FP16:
  python train_full.py --device cuda --precision fp16 --sequence-length 512

6K window, only if GPU memory allows:
  python train_full.py --device cuda --precision fp16 --sequence-length 6144

Custom licensed raw text / JSONL (preferred for genuine pretraining):
  python train_full.py --corpus /path/to/corpus --tokenizer /path/to/tokenizer.model --device cuda --precision fp16

For a custom corpus you must have rights to use its contents. The accepted
formats are UTF-8 .txt (one document per line) and JSONL with "text" or
"instruction"/"response" fields. The tokenizer is prepared from training
split text, not validation or test rows. Longer texts can also appear in JSONL
"text" records. See prepare_tokenizer.py.

LORA FINE-TUNING (AFTER PRETRAINING)
-----------------------------------
  python finetune_lora.py --base pretrain_checkpoints/last.pt --data datasets --device cuda --precision fp16

This trains small attention projection adapters and freezes all base weights.
Base checkpoint must be a completed or ongoing causal pretraining checkpoint,
not untrained random weights. The final adapter and merged SafeTensors
release are placed in lora_output/. LoRA alone does not create broad knowledge.

RESUME
------
The full launcher detects a compatible pretrain_checkpoints/last.pt and
resumes automatically; it will not silently reset the optimizer. Use the
same data files, tokenizer, sequence length, batch size, learning rate,
precision and accumulation. It resumes from the last checkpoint, not
necessarily the exact interruption point.

For LoRA, rerun the LoRA command with --resume and unchanged settings.

SAFETENSORS OUTPUT
------------------
After full pretraining completes:
  pretrain_checkpoints/release/model.safetensors
  pretrain_checkpoints/release/model.sha256
  pretrain_checkpoints/release/config.json
  pretrain_checkpoints/release/tokenizer.model
  pretrain_checkpoints/release/tokenizer.vocab
  pretrain_checkpoints/release/tokenizer_config.json
  pretrain_checkpoints/release/special_tokens_map.json
  pretrain_checkpoints/release/generation_config.json
  pretrain_checkpoints/release/README.md

Weights are exported as FP16 by default, while optimizer and resumable state
remain in pretrain_checkpoints/last.pt. The exported model uses custom
PyTorch code, not stock Transformers AutoModel. No fake tokenizer.json file
is generated for SentencePiece; tokenizer.model is the real tokenizer.

LOCAL CHAT FROM AN EXPORTED MODEL
---------------------------------
  python chat_export.py --release pretrain_checkpoints/release
  python chat_export.py --release pretrain_checkpoints/release --serve

Open http://127.0.0.1:8765 locally. Pretraining-only models may produce
poor chat responses until appropriate instruction tuning is completed.

TOKEN COUNTING AND DATA QUALITY
-------------------------------
The training logs count actual next-token targets and optimizer updates.
There is no arbitrary 100-step stop in the complete training command.
Repeated template samples are not equivalent to varied high-quality data.
A causal language model may memorize rare training passages. Bounded exact
text deduplication, licensed diverse data, source audits and out-of-sample
evaluation reduce risks but cannot guarantee zero copying or understanding.

CHECKPOINT COMPATIBILITY
------------------------
The new ~100M v1.1 architecture is incompatible with v1.0 86M checkpoints.
Start training from random initialization unless you have an exact v1.1
checkpoint. Never load .pt files from untrusted sources.
